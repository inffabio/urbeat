# Reusable Product Option Groups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist store-owned option-group templates and let sellers select copies of them while creating or editing products.

**Architecture:** Keep each product's option groups as independent snapshots. Add store-owned template tables for reusable definitions, expose a store-scoped read endpoint, and extend product create/update DTOs with an optional template identifier. The product service validates ownership, copies selected templates, and creates templates for newly authored groups only after a successful product save.

**Tech Stack:** .NET 9, EF Core, FluentValidation, ASP.NET Core, Angular 20 standalone, Ionic 8, Jest.

## Global Constraints

- Templates are always scoped to the current store and seller ownership.
- Existing product option groups and checkout behavior remain compatible.
- Product snapshots must not share mutable item rows with templates or other products.
- New-product reusable groups start unchecked; manually added groups start selected.
- Use EF migrations from `backend/`; do not run `dotnet ef database update`.
- Preserve strict TypeScript and existing storefront/dashboard visual patterns.
