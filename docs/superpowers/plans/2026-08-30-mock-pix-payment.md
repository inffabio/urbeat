# Mock Pix Payment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans (recommended) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a backend-driven Pix mock with a 60-second payment window that randomly approves between 10 and 50 seconds or expires at 60 seconds.

**Architecture:** `Payments:Provider=Mock` selects a mock payment strategy without calling Mercado Pago. Persisted simulation timestamps allow a hosted worker to transition payment and order state safely across process restarts; the existing frontend polling remains authoritative.

**Tech Stack:** .NET 9, EF Core 9, PostgreSQL, ASP.NET Core hosted service, Angular 20, Ionic 8, Jest.

## Global Constraints

- The mock applies only when `Payments:Provider` is explicitly set to `Mock`.
- The real Mercado Pago strategy remains unchanged when the provider is not `Mock`.
- Payment state remains authoritative in PostgreSQL.
- The payment window is exactly 60 seconds; approval may occur only between 10 and 50 seconds.
- Use UTC timestamps and server-provided expiration metadata.
- Do not generate real QR credentials or call Mercado Pago.
- Preserve retry without creating a second order.
- WebApi applies migrations at startup; do not use `dotnet ef database update`.
